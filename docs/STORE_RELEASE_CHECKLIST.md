# 스토어 출시 체크리스트

이 문서는 제품명과 로고가 정해지기 전에도 진행할 수 있는 준비와, 첫 스토어 업로드 전에 반드시 확정해야 할 항목을 분리한다.

## 현재 확인된 앱 구성

- iOS 15 이상, Android 7.0(API 24) 이상을 대상으로 한다.
- Android `targetSdk`/`compileSdk`는 36이다.
- 앱 권한은 인터넷 접근만 사용한다. 카메라, 사진, 위치, 연락처, 마이크 권한은 없다.
- 광고, 사용자 추적, 분석, 크래시 수집 SDK는 현재 앱 코드에 연결되어 있지 않다.
- 암기장, 카드, 가림별 학습 상태와 동기화 코드는 HTTPS 동기화 서버로 전송·보관된다.
- 별도 회원 계정은 없으며, 동기화 코드를 아는 기기끼리 같은 데이터를 연다.
- 현재 앱 이름 `시험암기`와 패키지명 `app.memory.dev`는 임시값이다.

## 이름과 무관하게 완료된 준비

- [x] iOS 시뮬레이터 Debug 빌드
- [x] Android Debug APK 빌드
- [x] 모바일 키보드가 올라올 때 WebView 가용 높이에 맞춰 화면 리사이즈
- [x] 카드 추가, 암기장 이름, 동기화 코드, 카드 편집 입력 화면의 키보드 접근성 확인
- [x] 서버 중단 시 오류·재시도 상태와 서버 재시작 후 데이터 복구 확인
- [x] Android 소프트 키보드 `adjustResize` 설정
- [x] 불필요한 민감 권한이 없는지 확인

## 첫 업로드 전에 확정

- [ ] 제품명과 스토어 표시 이름
- [ ] 영구 패키지명/Bundle ID
  - 예: `com.<개발자명>.<제품명>`
  - 첫 App Store Connect/Play Console 앱 생성 전에 정하고 이후에는 바꾸지 않는 전제로 선택한다.
- [ ] 앱 아이콘과 스플래시 이미지
- [ ] 버전 및 빌드 번호
  - iOS: `MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`
  - Android: `versionName`, `versionCode`
- [ ] 개인정보 처리방침 공개 URL
  - 앱 내부 설정 화면에서도 쉽게 열 수 있어야 한다.
- [ ] 지원 URL과 문의 이메일
- [ ] 스토어 설명, 검색 키워드, 카테고리, 연령 등급
- [ ] iPhone/iPad 및 Android 휴대전화 스크린샷
- [ ] 실제 기기에서 세로·가로 방향 정책 결정
- [ ] iOS 서명/프로비저닝 및 Android 업로드 키 설정
- [ ] TestFlight와 Play 내부 테스트 트랙에서 설치·업데이트·오프라인 복구 최종 확인

## 개인정보 표기 초안

현재 구현을 기준으로 다음처럼 신고하는 방향이 안전하다. 실제 제출 시 운영 서버, 로그 보존 정책, 호스팅 사업자의 처리 범위를 다시 확인한다.

| 항목 | 현재 구현 | 스토어 표기 방향 |
| --- | --- | --- |
| 암기장·카드·가림 상태 | 서버에 저장 | 사용자 콘텐츠 수집, 앱 기능 제공 목적 |
| 동기화 코드 | 서버 요청 식별에 사용 | 사용자/계정 식별자로 해석될 수 있는지 최종 검토 |
| 광고·추적 | 없음 | 추적 안 함 |
| 분석·크래시 SDK | 없음 | 수집 안 함 |
| 민감 기기 권한 | 없음 | 권한 사유 문구 불필요 |
| 전송 보호 | HTTPS | 전송 중 암호화 |
| 계정 삭제 | 계정 자체 없음 | 데이터 삭제 요청 방법을 개인정보 처리방침에 명시 |

Apple은 앱에서 서버로 전송해 보관하는 자유 형식 콘텐츠를 `Other User Content`로 분류하며, 개인정보 처리방침 URL과 앱 내부의 접근 가능한 링크를 요구한다. Google Play도 WebView를 포함해 기기 밖으로 전송되는 사용자 생성 콘텐츠를 수집으로 신고하도록 안내한다.

- [Apple App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)
- [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469)

## 심사 메모

Apple 4.2의 핵심은 네이티브 프레임워크 사용 개수가 아니라, 재포장된 웹사이트를 넘어 앱 자체로 충분한 효용과 앱다운 상호작용을 제공하는지다. 심사 노트에는 다음 실제 기능을 짧게 설명한다.

- 한 카드 안의 여러 가림을 개별적으로 만들고 판정한다.
- 몰랐던 가림만 다음 학습 대상으로 남긴다.
- 암기장·카드가 기기 사이에서 동기화된다.
- 서버가 일시 중단되면 데이터 손실로 오해하지 않도록 복구 상태와 재시도를 제공한다.
- 카드 추가 중에도 기존 카드를 훑어보며 연속 입력할 수 있다.

네이티브 전용 기능을 억지로 추가하는 대신, 현재 핵심 학습 흐름의 실제 효용과 모바일 상호작용을 스크린샷·심사 노트로 명확히 증명한다.
